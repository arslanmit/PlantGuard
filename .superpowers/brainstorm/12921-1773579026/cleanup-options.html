PlantGuard Cleanup Direction

Goal locked in: keep image, audio, chat, and a user-facing settings panel with model selection.

Option A: Surface-Only Cleanup
Header
Model Status
Tabs: Image | Audio | Chat | Settings
Hidden but still coded: tests, diagnostics, mobile AI framework

A. Surface-only cleanup

Remove obvious developer controls from the visible UI, but leave most internal testing and diagnostic code in place.

Pros

  • Lowest implementation risk
  • Fastest cleanup

Cons

  • Codebase still carries dead weight
  • Not a true "remove unnecessary things" pass
Option B: Product-First Cleanup
Header
Tabs: Image | Audio | Chat | Settings
Image analysis flow
Voice/audio flow
Chat flow
Settings: model selection + performance preferences

B. Product-first cleanup

Rewrite the main page around only the retained flows, move model selection into Settings, and remove runtime hooks for testing and status tooling.

Pros

  • Matches the product you described
  • Meaningful UI and code cleanup

Cons

  • Moderate edit scope
  • Needs targeted regression updates
Option C: Hard Prune
Header
Tabs: Image | Audio | Chat | Settings
Delete testing framework modules
Delete AI-agent/mobile tester paths
Delete related tests and make targets

C. Hard prune

Do the product-first cleanup, then aggressively delete testing and diagnostic modules that appear unused from the shipped app.

Pros

  • Smallest shipped surface
  • Removes the most dead code

Cons

  • Highest chance of breaking validation or internal tooling
  • Needs careful dependency auditing first

Recommendation: Option B. It removes the visible clutter and the runtime developer wiring without blindly deleting every internal tool module in one pass.
